## Financial safety principles that remain mandatory

1. Every posted journal entry group balances, but a balanced journal does not prove liquidity or profitability.
2. A vendor receivable is not refund cash. Customer refunds must not wait for vendor recovery where a refund is owed.
3. A complaint alone is not vendor debt. Recovery requires an authorised, evidence-based ruling and a contractual basis.
4. Verify gateway outcomes by provider references and reconciliation; screenshots are not proof of repayment.
5. Timeouts are uncertain outcomes, not proof of failure. Do not release reservations or retry transfers until reconciled.
6. Never mark a change verified based only on code inspection. Require tests, and use a staging/gateway sandbox for provider workflows.

**Finding:** The administrator's supplier onboarding and logistics-company onboarding forms accepted any LGA, allowing new supply or logistics partners to be based outside the approved Uyo launch area.

**Change:** Both onboarding handlers now validate the selected LGA and state before creating accounts or shops. Only Uyo, Akwa Ibom is accepted. The supplier's shop is created as the single primary pickup point; the supplier web portal cannot add another active/non-deleted shop or expand delivery coverage.

**Regression coverage added:** an administrator's attempt to onboard an Eket supplier is rejected before a vendor profile is created.

**Status:** Source and regression test committed on `docs/retailer-central-fulfilment-model`; tests/CI have not run for these latest commits. No merge or deployment.


## VM-AUD-088 — Align public product eligibility with supplier KYC requirements (21 October 2026)

**Severity:** High  
**Finding:** Public product eligibility required an active supplier profile and confirmed offer but did not require verified supplier KYC, while sourcing selection and supplier payout required verified KYC. This could advertise a product that the checkout sourcing service would reject.

**Change:** The public product eligibility scope now requires `vendor_profiles.kyc_status = verified`, aligning catalog visibility with sourcing eligibility. Added regression coverage for a confirmed offer from a supplier whose KYC status is no longer verified.

**Status:** Source and test committed on `docs/retailer-central-fulfilment-model`; automated tests have not run for this latest commit. No merge or deployment.


## VM-AUD-089 — Match web checkout bulky delivery preview to per-unit pricing (21 October 2026)

**Severity:** Medium  
**Finding:** The web checkout preview applied the bulky surcharge once for the selected product regardless of quantity, while authoritative checkout execution correctly applies the surcharge to each physical bulky unit. A customer ordering multiple bulky units could therefore see an underquoted delivery total before submitting checkout.

**Change:** Checkout preview now calculates the base delivery fee once and adds the configured bulky surcharge multiplied by the selected quantity, matching the authoritative checkout calculation. The preview resolves the confirmed Uyo supplier offer and does not use the catalog contributor's shop as the dispatch origin.

**Status:** Source committed on `docs/retailer-central-fulfilment-model`; automated tests have not run for this latest commit. No merge or deployment.


## VM-AUD-090 — Close legacy public supplier pickup reservation bypasses (21 October 2026)

**Severity:** High  
**Finding:** Although the newer API's pickup creation and payment actions were already disabled, legacy web routes could still create a 24-hour reservation against a private supplier shop and show the supplier's shop details to the customer. The public API reservation lookup also exposed legacy reservation details.

**Change:** Legacy web reservation creation and pass pages now redirect customers to Victorious MARKET support; public API reservation detail lookup now returns HTTP 410 without supplier details. Cancellation of a customer's own old reservation remains available so customers can close out stale reservations. Pickup exceptions must be arranged through central support.

**Status:** Source committed on `docs/retailer-central-fulfilment-model`; automated tests have not run for this latest change. No merge or deployment.


## VM-AUD-091 — Close customer tracking authorization through the compatibility supplier field (21 October 2026)

**Severity:** Critical  
**Finding:** The legacy web order-tracking controller authorized a supplier whenever its profile matched `orders.vendor_id`. Retailer-model orders retain that field only as a compatibility anchor for the primary source, so a private supplier could potentially open customer tracking despite supplier-terminal assignment scoping. The tracking view also displayed legacy vendor payout language and supplier branch identity.

**Change:** Supplier-profile authorization now applies only to legacy non-retailer orders. Customer tracking shows Victorious MARKET and describes supplier settlement as privately controlled; it no longer prints the legacy 90% vendor payout for retailer orders or identifies the supplier pickup shop.

**Status:** Source committed on `docs/retailer-central-fulfilment-model`; regression test and full branch-head CI verification remain outstanding. No merge or deployment.


## VM-AUD-092 — Lock the primary storefront to Uyo and the single retailer identity (21 October 2026)

**Severity:** Critical  
**Finding:** The primary storefront still accepted city/state and local/corridor scope parameters, listed supplier shops, filtered products using the catalog contributor's physical shop, and labelled products with supplier/branch names. This contradicted the permanent Uyo-only operating boundary and could hide a product whose actual eligible sourcing offer was in Uyo or reveal a private supplier's identity.

**Change:** The primary storefront now fixes its destination to Uyo, lists products with confirmed eligible supplier offers rather than filtering by the catalog contributor's shop, removes public shop listings and corridor discovery, and renders product cards as Victorious MARKET with Uyo local delivery messaging. The location selector is limited to Uyo.

**Status:** Source committed on `docs/retailer-central-fulfilment-model`; template/controller tests and branch-head CI remain outstanding. No merge or deployment.
